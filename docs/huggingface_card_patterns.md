# Hugging Face model-card patterns applied here

This is a read-only review of public Hugging Face metadata and model cards performed on 13 August 2026. No model weights or datasets were downloaded for this review. Download counts and likes are time-dependent signals, not quality measures.

## What is repeated in high-visibility time-series releases

| Observed pattern | Examples | Why it helps | Applied here |
|---|---|---|---|
| Searchable repository name: `publisher/family-version-size-backend` | `google/timesfm-2.5-200m-pytorch`, `amazon/chronos-2`, `Salesforce/moirai-1.1-R-small`, `ibm-granite/granite-timeseries-ttm-r3` | A user can identify the family, release, size and runtime before opening the card. | Recommended slugs are `gold-next-day-returns-extratrees` and `silver-next-day-direction-logistic`. |
| Complete Hub metadata above the fold | License, task tag, library tag, paper link and model-family tags are visible on the TimesFM, Chronos-2, Moirai and Granite cards. | Search, filtering and trust signals work before reading the full card. | Added `license`, `library_name`, `pipeline_tag`, asset/task tags and `research-only`. |
| Short value proposition before implementation detail | Chronos-2 starts with capability and scale; TimesFM starts with what the model is; Granite starts with supported tasks and deployment value. | The reader learns the model's job in seconds. | Added a TL;DR and a “Quick facts” table before the longer protocol. |
| Capability, data and limits are explicit | Chronos-2 documents univariate/multivariate/covariate support and context limits; TimesFM documents pretraining sources and checkpoint size; Granite documents tasks and training data. | It prevents readers from treating unlike models as interchangeable. | Cards state asset, horizon, target, causal feature rule, split, cost and what the artifact does not contain. |
| Copy-paste quickstart plus official links | The cards provide package-specific loading examples and links to papers, repositories, notebooks or deployment paths. | This turns a model page into a usable entry point instead of a leaderboard only. | Added a minimal `joblib` inference snippet and a direct source-repository link. |
| Benchmark tables and reproducibility notes | Chronos-2 and Granite expose benchmark/capability tables; the cards also identify papers, revisions or training-data sources. | A result is easier to compare and audit. | Added validation/test/robustness tables, foundation audit, statistical-test note, source snapshot and code revision. |
| Version and size are part of the family name | TimesFM uses `2.5-200m-pytorch`; Moirai uses `1.0-R-base` / `1.1-R-small`; Chronos uses `2`; Granite uses `ttm-r1/r2/r3`. | Variants remain discoverable without inventing marketing names. | Used a descriptive task/asset slug rather than a vague `gold-model` name. |

## Observed public signals

The time-series model catalogue sorted by downloads showed a strong concentration around recognizable families and variants: Chronos-2, Chronos-Bolt/T5, Granite-TTM, Moirai, TimesFM and other explicitly versioned models. The pages showed high activity for `amazon/chronos-2`, `google/timesfm-2.5-200m-pytorch`, `ibm-granite/granite-timeseries-ttm-r1/r2` and the Moirai family, but the counts change continuously. We therefore do not copy download or like counts into our cards and do not add badges that could become stale or imply endorsement.

Engagement is also helped by ecosystem links: papers, collections, Spaces, notebooks and deployment instructions. Those links are useful discovery paths, but they are not evidence that a model is superior on Gold/Silver returns.

## Naming decision for this project

Use these private-by-default Hub repository names:

```text
<namespace>/gold-next-day-returns-extratrees
<namespace>/silver-next-day-direction-logistic
```

The names say what the artifact predicts, the asset, and the selected estimator. If a future neural model replaces one of these, the estimator token should change while the asset/horizon vocabulary stays stable.

## Card structure now generated by `scripts/export_hf.py`

1. YAML metadata: license, task, library, tags and private-by-default marker.
2. TL;DR and research-only warning.
3. Quick facts: asset, horizon, target, features, split and costs.
4. Model details and artifact inventory.
5. Locked-test results and same-window foundation audit.
6. Paired statistical comparison and Reality Check interpretation.
7. Copy-paste local inference example.
8. Data provenance, intended use, limitations, citation and source code.

This intentionally favors durable scientific information over a leaderboard badge. It makes the card useful when download counts, model revisions or benchmark rankings change.
